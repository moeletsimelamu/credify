# Data dictionary — credit-risk data

> All data described here is **synthetic**. No real person, employer, bureau or lender is involved.

Three sources share one feature definition (`backend/app/modules/credit_risk/features.py`, `features-1.0.0`): the offline training dataset, the simulated bureau report, and the model input the API builds for a real Credify application.

## 1. Training dataset — `ml/data/borrowers.parquet`

Generated by `python -m credify_ml.generate` (`synthgen-1.0.0`, seed `20261118`, 50,000 rows). Git-ignored; reproducible. Its manifest (`manifest.json`) records the content SHA-256, the feature schema, the outcome process's coefficients and per-column statistics.

| Column | Type | Range | Missing means | Meaning |
|---|---|---|---|---|
| `borrower_id` | string | `SYN-000001`… | — | Synthetic identifier. Not a feature |
| `gross_monthly_income` | money | 0–2,000,000 | never missing | G from the affordability calculator |
| `net_monthly_income` | money | 0–2,000,000 | never missing | N from the affordability calculator |
| `employment_type` | category | PERMANENT, CONTRACT, SELF_EMPLOYED, PART_TIME, UNEMPLOYED, RETIRED | never missing | Current employment |
| `employment_tenure_months` | count | 0–720 | never missing | Months in current employment (0 when not employed) |
| `living_expenses_applied` | money | 0–2,000,000 | never missing | max(declared expenses, illustrative norm) |
| `existing_debt_instalments` | money | 0–2,000,000 | never missing | C: monthly instalments on existing credit |
| `num_credit_accounts` | count | 0–50 | never missing | Open credit accounts |
| `revolving_utilisation` | ratio | 0–2 | no revolving credit | Revolving balance ÷ limit |
| `missed_payments_12m` | count | 0–12 | never missing | Missed payments in the last 12 months |
| `months_since_delinquency` | count | 0–600 | never delinquent | Months since the last delinquency |
| `requested_amount` | money | 0–5,000,000 | never missing | Loan amount requested |
| `term_months` | count | 1–120 | never missing | Requested term |
| `loan_purpose` | category | the eight application purposes | never missing | Stated purpose |
| `debt_to_income` | ratio | 0–100 | no income | (C + I) ÷ G, four places |
| `repayment_burden` | ratio | 0–100 | no income | (C + I) ÷ N, four places |
| `residual_income` | signed money | −5,000,000–5,000,000 | never missing | N − E − C − I |
| `loan_to_income` | ratio | 0–1,000 | no income | Requested amount ÷ (12 × G), four places |
| `dgp_probability` | probability | 0–1 | — | The probability the generator used. Evaluation only; never a feature |
| `defaulted_12m` | 0/1 | — | — | Label: simulated 90+ days past due within 12 months |

I is the first month's instalment including the service fee, from the production amortisation engine. Amounts are in ZAR. The 17 feature columns are exactly what the model sees, in this order.

## 2. Audit attributes — `ml/data/audit_attributes.parquet`

Fairness auditing only. **Never** model inputs, never stored with applications, never available to the API.

| Column | Values | Use |
|---|---|---|
| `borrower_id` | joins to the dataset | — |
| `sex` | F, M | Group comparisons in the fairness report |
| `age_band` | 18-24, 25-34, 35-44, 45-54, 55-64, 65+ | Group comparisons in the fairness report |

Injected effects (documented in the manifest): the F group's income is multiplied by 0.88; income and the employment mix depend on age band. Neither attribute affects the default outcome directly.

## 3. Simulated bureau report — `credit_bureau_reports`

Pulled once per application at submission by `app/modules/credit_risk/domain/bureau.py` (`bureau-sim-1.0.0`). Deterministic: the same applicant's synthetic reference always yields the same report. Provider is always `SIMULATED`; no real bureau is contacted.

| Field | Range | Meaning |
|---|---|---|
| `missed_payments_12m` | 0–12 | 18 % of applicants have 1 + Poisson(0.8) missed payments |
| `months_since_delinquency` | 0–96 or NULL | 0–11 with recent misses; 12–96 for 18 % of the rest; NULL otherwise |

## 4. Model input for a Credify application

Built by `app/modules/credit_risk/service.py` at scoring time, from data the application already holds:

| Feature | Source in Credify |
|---|---|
| Incomes, living expenses, existing debt, debt-to-income, repayment burden, residual income | The application's latest affordability assessment (exact stored figures) |
| `employment_type`, `employment_tenure_months` | The applicant's current employment record (tenure = whole months since its start date) |
| `num_credit_accounts` | Count of active credit commitments |
| `revolving_utilisation` | Σ balances ÷ Σ limits over credit-card and store accounts with a limit (NULL if none; capped at 2) |
| `missed_payments_12m`, `months_since_delinquency` | The simulated bureau report |
| `requested_amount`, `term_months`, `loan_purpose` | The application |
| `loan_to_income` | Computed by the feature builder |

The stored `feature_snapshot` holds these 17 values, their order, the feature-schema version and their sources (affordability version, bureau simulator version, date).

## 5. Never used as features

Age and date of birth, sex and gender, race and ethnicity, marital status, dependants, religion, nationality, disability, health, language, postal code, city, region, province and address, names, email and phone (`PROTECTED_ATTRIBUTES` in the feature module). Geographic fields are excluded as proxies. Tests assert none of these can reach the model, and the registry refuses a model whose schema contains one.
